# Лабораторна робота №4: Модульне тестування за допомогою TestNG

**Виконав:** Тимур

## Мета роботи
[cite_start]Набуття практичних навичок використання TestNG для модульного тестування: побудова Maven-проєкту, застосування анотацій життєвого циклу, групування тестів, параметризація через @DataProvider та налаштування запуску через testng.xml[cite: 41].

## Виконані завдання:
1. [cite_start]**Перехід на TestNG:** Проєкт переведено з JUnit Jupiter на TestNG шляхом оновлення залежностей у `pom.xml`[cite: 336, 337].
2. [cite_start]**Організація запуску:** Створено файл `testng.xml` для явного керування тестовим набором[cite: 346, 572].
3. [cite_start]**Модульні тести:** Реалізовано 9 тестових методів для класів `Pet`, `Dog` та `Adopter`[cite: 351, 352].
4. [cite_start]**Фікстури:** Використано анотацію `@BeforeMethod` для підготовки об'єктів перед кожним тестом[cite: 156, 338].
5. [cite_start]**Групування:** Тести розділені на групи `smoke`, `domain` та `negative`[cite: 208, 339].
6. [cite_start]**Параметризація:** Додано `@DataProvider` для тестування створення тварин з різними наборами даних[cite: 209, 345].
7. [cite_start]**Аналіз покриття:** Налаштовано плагін JaCoCo для генерації звіту про покриття коду[cite: 347, 454].

## Порівняння JUnit Jupiter та TestNG
* [cite_start]**Конфігурація:** TestNG надає зручний XML-файл (`testng.xml`) для керування запусками, тоді як у JUnit конфігурація частіше прихована або робиться через анотації в коді[cite: 141, 309].
* [cite_start]**Параметризація:** Механізм `@DataProvider` у TestNG сприймається як більш гнучкий для передачі складних об'єктів у порівнянні з `@ParameterizedTest` у JUnit[cite: 141, 276].
* [cite_start]**Групування:** TestNG має вбудовану підтримку груп безпосередньо в анотації `@Test`, що спрощує вибірковий запуск тестів[cite: 141, 274].
